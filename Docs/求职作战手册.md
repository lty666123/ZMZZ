> 用途：从 2026-10-11 到 2027 年春招的完整行动清单，配合 `ZMZZ-Unity` 工程使用。
> 用法：每周一打开第 6 节「周计划」，做一项勾一项；踩到新坑追加到《错题本.md》。
> 前提假设：2027 年 6-7 月毕业，主战场是 2027 年 2-4 月春招；每周可投入约 20 小时。
> 配套文档：《游戏企划案.md》《交接说明.md》《错题本.md》《UI框架说明.md》
> **知识答案都在《面试知识详解.md》里**——第 4 节只负责列清单和打勾，解释和例子去那一份看。
> 建立日期：2026-10-11

## 0. 三条铁律

1. **项目优先于八股。** 面试官先判断你能不能交付，再问你知不知道原理。没有能跑的东西，背得再熟也是空的。
2. **帧计数优先于秒。** 确定性是动作游戏的技术底座，也是你能讲出的第一个「专业」理由。
3. **边做边投。** 不要等「准备好」。简历每两周改一版，用真实面试反馈来校准方向。

## 3. 第一阶段：工程立项化（W1-W6）

### 3.1 P0 · 必须做

- [ ] **A1 · 建 git 仓库并推送到 GitHub**
  - `git init`，`.gitignore` 排除 `Library/`、`Logs/`、`.verify/`、`.backup/`、`obj/`、`*.csproj`、`*.sln`
  - 按里程碑提交，一个系统一个 commit，写清楚「做了什么、为什么」
  - 私有仓库即可，面试时给链接
  - 验收：GitHub 上能看到 20+ 条有意义的 commit

- [ ] **A2 · 命中特效对象池**
  - 现在 `HitSpark.Spawn` 每次 `new GameObject` + `AddComponent<SpriteRenderer>` + `Destroy`
  - 改用 `UnityEngine.Pool.ObjectPool<T>`（Unity 2021+ 自带，不用手写）
  - 池化对象必须重置：位置、缩放、颜色、计时器、`SetActive`
  - 验收：连续命中 100 次，Profiler 中 `HitSpark` 相关 GC Alloc 为 0

- [ ] **A3 · 攻击检测零 GC**
  - `Hitbox.FixedUpdate` 里的 `Physics2D.OverlapBoxAll` **每次调用都新建数组**
  - 换成写入预分配容器的重载：`Physics2D.OverlapBox(center, size, 0f, filter, _results)`
  - 把 `GetComponentInParent<Hurtbox>()` 的结果缓存进 `Dictionary<Collider2D, Hurtbox>`
  - 验收：战斗帧的 GC Alloc 从 X KB/帧 降到 0

### 3.2 P1 · 应该做

- [ ] **A4 · 存档系统**
  - `JsonUtility` + `Application.persistentDataPath`
  - 存：关卡进度、角色等级、装备、设置（音量、按键）
  - 必须知道的三个坑：不支持 `Dictionary`、不支持多态、字段要 `[Serializable]` 且 public 或带 `[SerializeField]`
  - 加分做法：存档版本号 + 迁移逻辑（旧存档不能把新版本读崩）
  - 验收：退出重进后进度还在；手改存档文件不会崩溃

- [ ] **A5 · 音频系统**
  - `AudioManager` 常驻单例 + 音效对象池（与 A2 同一套思路）
  - `AudioMixer` 分 Master / BGM / SFX 三组，设置面板接上音量滑块
  - 至少接上：攻击挥空、命中、被格挡、弹反成功、Boss 前摇、受击、死亡
  - 验收：不看画面只听声音，能分辨「弹反成功」和「普通格挡」

- [ ] **A6 · 性能实测记录**
  - Profiler 截两张图：优化前 / 优化后（GC Alloc、DrawCall）
  - 用 Frame Debugger 看一帧的 DrawCall 数量，做一次 Sprite Atlas 合批
  - 验收：README 里有可对比的数据，不是「我觉得变快了」

### 3.3 P2 · 锦上添花

- [ ] **A7 · 补完关卡闭环**
  - 进关 → 清怪 → 宝箱 → 关底 Boss → 结算界面 → 存档 → 重开
  - 现在缺的是掉落、结算界面、关卡切换三个环节
  - 验收：陌生人拿到构建包，不看说明能自己玩通一轮

- [ ] **A8 · 配置表外置**
  - `AttackProfile` 目前内嵌在 `CombatTuning.asset` 里
  - 进阶做法：CSV/JSON 配置表 → 编辑器导入工具 → 生成 SO
  - 要能讲清 `Resources` 的三个缺点（全量打进包、无法卸载、路径字符串易错）与 `Addressables` 的收益

## 6. 作品集三件套

### 6.1 GitHub 仓库

- 有意义的 commit 历史
- README 结构：一句话概念 → 玩法说明 → 技术栈 → 系统架构图 → 技术亮点 → 已解决的问题 → 运行方式

### 6.2 可试玩构建 + 视频

## 7. 面试准备

### 7.1 三个必被问的问题

**Q1「介绍一下你的项目」**

90 秒结构：一句话是什么 → 你负责哪部分 → 最有技术含量的一个系统 → 结果（数据或反馈）。

**Q2「讲一个你遇到的最难的问题」**

从《错题本.md》里挑最硬的一条，按 STAR 讲：背景 → 现象 → 排查过程 → 根因 → 怎么修的 → 学到了什么。
推荐素材：命中停顿与暂停抢 `Time.timeScale`、`Vector2` 分量写反导致「有时候能跳有时候不能」、泛型类型对不上导致静默失败。

**Q3「为什么用帧而不是秒来计算时间？」**

确定性 → 跨设备可复现 → 帧同步的基础。用秒累加会随帧率漂移，且无法回放。

### 7.2 必须能自圆其说的设计决策

| 决策 | 你要能说出的理由 |
| --- | --- |
| 全局 hitstop 用 `Time.timeScale = 0` | 冻结期间 `Update` 仍运行，所以用 `unscaledDeltaTime` 倒计时；代价是 UI 和音频也停 |
| 如果要只冻结战斗呢？ | 做「局部时间」：每个战斗对象持有自己的时间缩放系数 |
| 全项目帧计数 | 确定性、可复现、便于调试慢动作 |
| 不可格挡招式 | 逼玩家用满工具箱，避免一招走天下 |
| 格挡与闪避共用体力 | 制造取舍，防止无脑连滚 |
| 数值全外置 ScriptableObject | 调参不用改代码、不用重新编译，策划也能改 |
| 用物理查询而非触发器做判定 | 时序确定、可用 Gizmos 直接画出来调 |
