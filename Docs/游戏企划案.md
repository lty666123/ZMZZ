# 2D ZMZZ · 游戏企划案

> 状态：企划中 · 起始日期 2026-10-10
> 用途：这是我们俩的讨论工作台。不确定的地方先写「待定」，聊到一次就更新一次。
> 唯一原则：**先把一个循环做到能玩，再谈内容量。**
> 工程：`ZMZZ-Unity`（Unity 2022.3.62f3c1 · URP 2D）· M1 战斗原型已可试玩，见文末第 12 节。

## 0. 一句话概念

**类型定位（已定 2026-10-10）**：PC 单机 · 2D 横版动作 · 以战斗为核心的闯关

**成长定位（已定 2026-10-10）**：横版动作 RPG —— 角色等级 + 武器装备双线成长；刷怪得经验与掉落，宝箱与怪物掉落提供装备；有剧情，剧情可跳过。

**战斗定位（已定 2026-10-10）**：**技巧为主、数值为辅**。难度来自 Boss 的连招与读招；等级与装备只提供容错宽度和构筑选择，不做数值碾压；明确排除「枯燥刷级」这条成长路径。

**一句话概念**：待定 —— 现在缺的只有主角、世界和动机。句式参考：一个「谁」，为了「什么」，在「哪里」，用刀剑和成长对抗「什么」。

参考句式：

- 一个「什么样的主角」，在「什么处境」，为了「什么目的」，用「什么独特手段」。
- 示例：一个靠钩爪摆荡的流浪猫，在被水淹没的城市里，为了找回主人留下的录音带，用摆荡和抓取躲避追兵。

## 1. 核心循环

玩家每 30 秒左右重复一次的动作。整个游戏的发动机。

| 环节 | 玩家做了什么 | 游戏给出什么反馈 | 为什么爽 |
| --- | --- | --- | --- |
| 进入 | 待定 | | |
| 行动 | 待定 | | |
| 反馈 | 待定 | | |
| 奖励 / 成长 | 待定 | | |
| 回到起点 | 待定 | | |

以上是占位。按「战斗闯关」的定位，草案长这样（**待确认**）：

| 环节 | 玩家做了什么 | 游戏给出什么反馈 | 为什么爽 |
| --- | --- | --- | --- |
| 进入 | 走进关卡段，敌人出现 | 镜头推近、音乐变化、敌人起手 | 预期感，「要来一场了」 |
| 行动 | 观察起手 → 走位、闪避、抓时机出手 | 攻击判定、命中音效、敌人硬直 | 我的判断被兑现 |
| 反馈 | —— | 命中停顿、震屏、击退、特效 | 力量被直接映射出来 |
| 奖励 / 成长 | 清场，走向下一段 | 掉落、结算、解锁 | 目标达成 |
| 回到起点 | 面对更强的敌人或新机制 | —— | 循环升级 |

**判定标准**：把「行动 → 反馈」单独拿出来玩 10 分钟还觉得爽，核心循环才算立住。做不到就还没到做美术和剧情的时候。

### 1.1 三层循环结构（草案）

这类游戏不是一个循环，是几个套在一起的循环。任何一层断裂，整体就散架：

| 层级 | 时长 | 内容 | 断裂的后果 |
| --- | --- | --- | --- |
| 战斗循环 | 秒 | 走位 → 攻击 → 命中反馈 → 躲避 → 击杀 | 打起来不爽，其余全部白费 |
| 关卡循环 | 分钟 | 进关 → 清怪推进 → 开宝箱 → 关底 Boss → 结算 | 关卡没了节奏，退化成单纯刷怪 |
| 成长循环 | 小时 | 升级 / 换装 / 强化 → 挑战更难的关 → 掉更好的装备 | 没有变强的实感，玩家流失 |
| 剧情线 | 贯穿全程 | 关卡推进 → 剧情 → 新目标 | 玩家不知道自己为什么在打 |

其中「战斗」和「成长」是会互相打架的，见第 9 节风险 5 —— 这是本作最核心的设计难题。

## 2. 特色与差异点

只留 1～2 个。多了等于没有。

- 候选一：**硬核动作手感 + 明确的数值成长**。多数动作游戏没有成长，多数刷宝游戏手感平庸，两者兼顾的作品不多，这是天然空位。
- 候选二：**「打」与「找」并重的装备获取**。怪物掉落与探索宝箱两条路都成立，让清怪党和探索党都有理由继续玩。

要避免的伪特色：「画面精美」「手感好」「内容丰富」「玩法多样」——这些是及格线，不是特色。

## 3. 平台与目标玩家

| 选项 | 操作方式 | 优势 | 代价 |
| --- | --- | --- | --- |
| PC 单机（Steam / itch.io） | 键鼠 / 手柄 | 操作上限高，适合硬核动作；开发最自由 | 需要玩家坐下来，竞争激烈 |
| 手机 | 触屏 | 触达广，休闲题材友好 | 操作深度受限，UI 要重做，需要适配 |
| Web / 微信小游戏 | 点击 / 触屏 | 传播快，试玩门槛极低 | 包体限制严，性能预算低，变现路径不同 |

**当前选择**：**PC 单机**（已定 2026-10-10）

影响：

- 操作上限高，能做有深度的战斗；键盘和手柄都能用
- 不用考虑触屏适配和包体限制，资源可以放开用
- 代价：玩家要坐下来玩，Steam 上同类型竞品密集，只能靠手感和特色取胜

## 5. 玩法系统

### 5.1 操作
**已定（2026-10-10）**：左右移动、跳跃、普通攻击（可连段）、技能（消耗资源）、**闪避**、**格挡 / 弹反**、道具使用；键鼠与手柄双支持。

关键点：**闪避和格挡同时存在，但职责必须分开**，否则玩家只会挑更强的那一个用，另一个动作等于白做。

| 动作 | 定位 | 用来应对什么 |
| --- | --- | --- |
| 闪避 | 位移型应对，消耗体力，无敌帧短 | 范围攻击、投技、无法格挡的重击、脱离包围 |
| 格挡 | 站桩型应对，代价是硬直与体力 | 可格挡的连续攻击，稳吃对方的节奏 |
| 弹反 | 格挡的精准版本，窗口极短 | 高风险高回报，是打断 Boss 连招的主要手段 |

机制细节见 5.9。

### 5.2 数值与手感
待定（移动速度、跳跃高度、受击硬直、屏幕震动……这些是「手感」的真正来源）

参数清单见第 8.1 节。

### 5.3 关卡结构

**已定（2026-10-10）**：**区域制的一片式横版地图 + 传送锚点**。

含义拆解（我按你的描述理解，若不对直接改）：

- 「一片式」：每个区域是一整块横向连贯的横版场景，地形是手工设计好的，**不是**泰拉瑞亚那种逐格自由建造、挖掘的世界
- 明确不做：地形破坏、自由建造、无缝开放大世界
- 「传送锚点」：区域之间由锚点连成路网，锚点兼作传送点与存档恢复点

| 层级 | 内容 |
| --- | --- |
| 世界 | 若干区域，通过传送锚点连成一张可回溯的路网 |
| 区域 | 一整片连续的横版场景，内部有主路径与探索支线 |
| 关卡段 | 区域内部的战斗遭遇与平台挑战的节奏编排 |
| 锚点 | 传送、存档、恢复、敌人刷新，同时是「进度节点」 |

锚点的作用（这一条设计好，很多系统都能省事）：

- 快速旅行：已激活的锚点之间任意传送
- 存档与恢复：类似篝火，恢复状态、保存进度
- 敌人刷新：离开区域再进入时，怪与宝箱按规则重置
- 剧情触发：部分剧情在抵达锚点时播放

支线区域的价值：宝箱、材料、可选挑战（精英怪）藏在这里，让「探索宝箱」这条装备来源有真实意义，同时不强迫所有人走回头路。

待定：区域数量、区域之间是场景切换还是无缝加载、锚点能否被敌人打断。

### 5.4 敌人与挑战

**已定方向（2026-10-10）**：**小怪吃数值，精英与 Boss 吃技巧**。

| 层级 | 设计取向 | 说明 |
| --- | --- | --- |
| 普通小怪 | 数值主导 | 有受击反馈、可击退；等级上来了能顺畅推过去，提供推进的爽感 |
| 精英怪 | 技巧为主 | 有明确起手与破绽，惩罚走位失误 |
| Boss | 纯技巧 | **连招为核心**，读招、闪避、弹反是唯一解法，堆数值赢不了 |

Boss 设计要求：

- 连招分段，每段之间留出可反应的窗口
- 至少有一条「必须弹反」或「必须闪避」的招式，逼玩家用满工具箱
- 连招可被打断（弹反削韧性），给玩家正向反馈
- 有明确的破绽期（大招后的硬直），作为输出窗口

群怪的「围攻节奏」需要专门设计 —— 不能所有敌人同时扑上来，否则动作手感会被淹没。

### 5.5 进度与成长

**已定方向（2026-10-10，v2）**：等级 + 装备双线成长，但**数值影响力被有意压低**。

因为难度归属已定为「技巧为主」，成长就不能是数值碾压，必须换一个定位：

| 成长线 | 获取方式 | 提供什么 | 定位 |
| --- | --- | --- | --- |
| 角色等级 | 击败怪物获得经验 | 血量、体力上限、技能解锁、少量属性 | **容错宽度**，不是伤害碾压 |
| 武器装备 | 怪物概率掉落 / 探索宝箱 | 小幅属性、词条、手感与招式差异 | **构筑选择**，不是数值堆叠 |
| 装备强化 | 消耗掉落材料 | 小幅提升已有装备 | 给多余材料一个出口 |

三条硬性约束（防止成长跑偏成数值游戏）：

1. **同进度区间内，装备好坏的伤害差距控制在 30% 以内**：能感觉到差别，但不足以让 Boss 变成无脑推
2. **等级上限跟随剧情进度解锁**，达到当前上限后经验溢出转化为强化材料 —— 这样「刷级」自然失效，想变强只能往里推进
3. **Boss 战的关键机制不吃数值**：弹反削韧、破防增伤与伤害数字无关，等级再高也得老老实实弹反

待定：等级上限具体数字？属性随等级是线性还是曲线？装备是否有品质分级（白/绿/蓝/紫）？强化是否设失败率？

### 5.6 掉落系统

**已定方向（2026-10-10）**：装备有两条来源 —— 怪物概率掉落、探索宝箱；材料用于强化装备。

设计建议（我的意见，供你拍板）：

1. **要有保底感**：纯概率掉落会让玩家反复刷到怀疑人生。建议「材料必掉 + 装备概率掉」的组合。
2. **掉落表必须数据驱动**：敌人 → 掉落表 → 物品，全部配在数据文件里，不写死在代码里。改数值不该动代码。
3. **前期给确定性**：第一件装备放在流程必经的宝箱里，让玩家立刻理解「装备能让我变强」。
4. **要不要专属掉落**：Boss 限定掉落是很好的动力，但也意味着必须刷 Boss。

**注意（因为数值被压低）**：掉落的价值必须从「更高的数字」转移到「更多的可能」—— 词条组合、招式差异、特殊效果、外观收集。否则玩家没有刷的理由，掉落系统会空转。

待定：稀有度分级、具体掉率、是否有专属掉落。

### 5.7 剧情系统

**已定方向（2026-10-10）**：游戏有剧情，且**必须支持跳过**。

实现上这不是「加个跳过按钮」，而是一套统一的剧情播放器：

- 对话与旁白（文本框 + 立绘或头像）
- 触发式演出（进入某区域、击败某 Boss 后触发）
- 统一接口：播放 / 快进 / 跳过 / 已读标记

**跳过的连带问题必须一起设计，否则跳过等于丢信息**：

- 记录已播放节点，支持「剧情记录 / 回想」查看
- 跳过时给一句极简摘要，例如「你答应帮村民找回丢失的灯」
- 保证跳过不会跳掉关键教学和关键物品获取

待定：呈现形式（纯对话 / 漫画分镜 / 预渲染过场）？世界观？主线结构？

### 5.8 存档系统（提前提醒）

等级、经验、装备、强化等级、剧情进度、已探索区域全部要存。**存档的数据结构要及早定**，因为它一旦有玩家就难改（旧存档兼容）。建议从第一天就带版本号字段，用可版本化的 JSON 或 ScriptableObject 快照。

### 5.9 战斗核心机制：格挡弹反与韧性（已定 2026-10-10）

这是本作战斗系统的核心，也是「技巧为主」定位的落点。

**机制链**：格挡 → 精准弹反 → 削减韧性 → 韧性跌破阈值 → 破防，期间受到伤害增加 → 打出爆发窗口

| 环节 | 规则 | 建议起始值（全部可调） |
| --- | --- | --- |
| 格挡 | 挡下正面可格挡的攻击，消耗体力，自身有短暂硬直 | 每次消耗体力 15% |
| 弹反窗口 | 格挡动作开始后极短时间内被击中，判定为弹反 | 命中前 6～10 帧 |
| 弹反成功 | 无伤、不消耗体力、打断敌人当前连招段落 | —— |
| 韧性条 | 精英与 Boss 持有，独立于血条 | 满值 100 |
| 削韧 | 弹反削一大截，普通攻击削极小一截 | 弹反 20～25，轻击 3～5 |
| 韧性恢复 | 一段时间未被打中后开始回复 | 3～5 秒后，每秒 8～10 |
| 破防状态 | 韧性低于阈值触发，受到伤害增加并陷入硬直 | 阈值 30，伤害 ×1.5，持续 3～5 秒 |
| 破防结束 | 韧性重置为满值 | —— |

设计要点：

- **弹反风险要真实**：弹早弹晚都要吃伤害，否则玩家会无脑连点格挡，机制立刻失效
- **韧性必须会恢复**：否则玩家可以龟缩慢慢磨，Boss 战退化成站桩
- **小怪不设韧性条**，只有硬直；韧性条是精英与 Boss 的专属语言
- 破防增伤是「奖励技巧」，不是隐形的伤害成长，所以数值可以给得大方

## 6. 美术与音频方向

**现状（2026-10-10）**：没有任何角色模型与动作模组。

这是需要解决的技术性障碍，但**它不是做战斗原型的障碍**。

### 6.1 关键判断：先做手感，再谈美术

2D 动作游戏的动作量比直觉大得多。一个「能打」的主角至少需要：站立、奔跑、起跳、下落、落地、攻击 1、攻击 2、受伤、死亡 —— 9 套动画；再加 3 种敌人就是 30 套以上。所以顺序应该是：

| 阶段 | 主角长什么样 | 目的 |
| --- | --- | --- |
| 原型期 | 纯色矩形 / 胶囊 | 验证打击感与战斗节奏，此时美术是干扰项 |
| 垂直切片 | 免费素材或生成的占位图 | 验证画面观感与动画节奏 |
| 量产期 | 正式美术 | —— |

好处：从方块换成真图，只需要替换 Sprite 和动画控制器，战斗代码一行都不用改。

### 6.2 美术来源方案（按推荐顺序）

1. **占位方块先行**（推荐）：0 成本、0 等待，最快验证好不好玩
2. **免费素材包**：Unity Asset Store、itch.io 上有大量带完整动作集的 2D 角色包，适合做垂直切片
3. **我来生成**：我可以出像素风或手绘风的角色与动作序列图，适合占位和概念验证，不建议直接当正式资产
4. **2D 骨骼动画**：一张立绘拆件绑骨，动作量大时比逐帧省功夫（Unity 2D Animation 包）
5. **外包 / 约稿**：等玩法定型再花钱，别提前投入

注意：2D 没有 Mixamo 那种现成动作库，动作必须逐帧或绑骨做出来。

## 7. 范围与里程碑

### 7.1 MVP 定义

MVP = 「能玩、能判断好不好玩」的最小版本。对本项目来说是：

> 一个纯色方块主角，在一张测试地图上，和一种敌人打一场，能赢也能输，而且打起来**有手感**。

不需要美术、不需要剧情、不需要菜单。

但要提醒：本作是「战斗 + 成长」双轮驱动，所以 M1 之后要尽快验证成长线，否则容易做成一个「手感不错但不知道为什么打」的游戏。建议紧接一个 M1.5：击杀得经验 → 升级加属性 → 掉落一把可替换的武器。

### 7.2 里程碑

| 阶段 | 产出 | 预估 |

### 8.1 动作游戏专项：战斗手感清单

下面这些全部由代码和数值决定，与美术无关，**方块阶段就能全部调好**。这是「打击感」的真正来源：

| 项 | 说明 | 典型起始值 |
| --- | --- | --- |
| 攻击三阶段 | 前摇 / 判定 / 后摇，决定能不能被躲、连招是否利落 | 前摇 8～12 帧，判定 3～6 帧，后摇 10～20 帧 |
| 命中停顿 hitstop | 命中瞬间双方短暂冻结，打击感的主要来源 | 2～6 帧，重击更长 |
| 击退与受击位移 | 敌人被打退的距离 | 重击 0.3～1 格 |
| 屏幕震动 | 镜头短促位移 | 命中 0.05～0.15 秒 |
| 无敌帧 | 受击后短暂无敌，避免被连死 | 0.5～1 秒 |
| 输入缓冲 | 提前按下的指令不丢失 | 6～10 帧 |
| 取消窗口 | 后摇能被闪避或下一段连招打断 | 后摇后 30%～50% |
| 受击硬直 | 敌人被击中后的僵直时间 | 轻击 6～10 帧，重击更长 |

## 12. 工程现状（截至 2026-10-10）

**工程位置**：`E:\unity-codex\2D ZMZZ\ZMZZ-Unity`　·　Unity 2022.3.62f3c1 · URP 2D

### 12.1 怎么跑起来

1. Unity Hub → 项目 → 添加 → 选择 `E:\unity-codex\2D ZMZZ\ZMZZ-Unity`
2. 打开后双击 `Assets/Scenes/CombatPrototype.unity`
3. 按 Play

### 12.2 操作

| 按键 | 动作 |
| --- | --- |
| A / D 或 ← / → | 移动 |
| 空格 | 跳跃（按得越短跳得越低） |
| J | 攻击，三连段（后摇期间可继续接） |
| K | 闪避（前段有无敌帧，消耗体力） |
| L（按住） | 格挡；**举盾瞬间被击中 = 弹反** |
| T | 切换慢动作 1x / 0.5x / 0.25x / 0.1x，用来逐帧观察 |
| R | 重开一局 |

### 12.3 已经做完的

- **UI 框架**：UIManager（面板注册 / 四层层级 / 开关栈 / Esc 逐层返回 / 场景加载遮罩）+ UIPanel 基类 + UIFactory 零件库 + UITheme 配色字体，详见 `Docs/UI框架说明.md`
- **入口界面**：开始游戏 / 设置 / 退出游戏；设置面板含主音量、全屏、垂直同步、分辨率（存 PlayerPrefs）；战斗内 Esc 唤出暂停菜单
- 玩家：移动、跳跃（土狼时间 + 跳跃缓冲 + 松手截断）、三连段、闪避无敌帧、格挡、弹反、体力、受击无敌帧、死亡
- Boss：连招驱动 AI（三连斩 / 不可格挡的突进斩 / 带大破绽的重砸）、颜色区分的前摇、韧性条、破防增伤、被弹反打断、破绽窗口
- 战斗规则：命中停顿、击退、屏幕震动、命中特效、破防伤害倍率
- HUD：双方血条、体力、Boss 韧性、破防提示、弹反窗口提示
- 调试：全部数值集中在 `Assets/Resources/CombatTuning.asset`，Play 模式下边玩边改
- 工具：菜单 `ZMZZ / 构建战斗原型场景`，随时用代码重建场景
- 测试：8 个 PlayMode 用例（战斗规则 + 韧性回复 + 场景冒烟），命令行可跑
