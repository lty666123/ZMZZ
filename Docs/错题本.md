## 自检清单（每次改完代码，按这个过一遍）

- [ ] **条件方向对不对？** 「没有就补上」的代码，条件必须是"缺少时"（`_x == null`、`!Contains`）。写反了不报错，只会静默变 null。
- [ ] **拉到的引用会不会是空的？** 空引用会让**它后面所有代码都不执行**——包括你没写错的那些。
- [ ] **写在事件回调里的代码，前面一行抛异常，后面全部作废。** 所以先做检查、再做操作，别把无关的事串在一起。
- [ ] **我传进去的回调，真的有人调用它吗？** 存了不用等于没写。
- [ ] **"看不见"不等于"消失了"。** 不关 `blocksRaycasts`，一块透明的板子照样挡住鼠标点击。
- [ ] **判断浮点数别用 `!=`。** 用 `< 1f` / `> 0f` 这种范围判断更稳。
- [ ] **改完立刻看一眼 Console。** Unity 的报错带文件名和行号，双击直接跳过去——这是免费送的定位工具。
- [ ] **注释和代码要对得上。** 注释说"时长"、代码写"速度"，一个月后自己会被绕进去。
- [ ] **显示文字前，先确认这个字体里有这些字形。** TMP 默认字体只有英文，中文必须换成中文字体资产。
- [ ] **一次改完所有相关处，并立刻按「最长的那条路径」测一遍。没测就等于没改。** 只改一处，bug 会换个样子再出现。
- [ ] **同一个规则只写一遍。** 文件名、路径、key 名，只要在两处各写了一遍，迟早会不一致。
- [ ] **报一堆错时，先只看第一条。** 后面的多半是它带出来的；改掉根因，十几条会一起消失。
- [ ] **访问修饰符只在类里用。** `public` / `private` / `protected` 出现在方法体里一定是写错了。
- [ ] **参数顺序对不对？** `new Vector2(横, 纵)`、`SetSize(宽, 高)` 这类"约定顺序"写反了不报错，只让行为变得诡异。
- [ ] **访问数组下标前，长度够不够？** `items != null` 不代表有元素；访问 `[0]` 前还要确认 `Length > 0`。网络数据可能还没返回，也可能成功返回空列表。
- [ ] **修改 UI 布局时，有没有组件正在控制它？** Scrollbar 会控制 Handle 的锚点，ContentSizeFitter 会控制内容尺寸；异常偏移、负尺寸会与自动计算叠加。

### 错题 041 · 2026-11-18 · 云存档用单帧耗时判断上传时间点，后续上传被阻止

**代码证据**：CloudSaveClient.Update 判断 Time.unscaledDeltaTime < nextUploadTime；UploadPendingSave 的 finally 又设置 nextUploadTime = Time.unscaledDeltaTime + 3f。前者通常为零点零几秒，后者约为三秒，正常帧率下后续检查持续返回，三秒过去也不会解除。

**修法**：两处都使用 Time.unscaledTime：检查当前累计时间是否到达下一上传时间，并在结束后设为当前累计时间加三秒。保留原来的串行上传及失败重试结构。

**教训**：unscaledTime 是从启动开始累计的时间，适合记录到期时间点；unscaledDeltaTime 是本帧时间间隔，适合累加计时或按秒计算移动。不能将单帧间隔直接与累计截止时间比较。

**状态**：已核对两处源码并给出用户自行修改的位置；未运行 Unity 复现，未修改游戏源码。若仍失败，需要继续看首次上传或读档的实际错误日志。

### 错题 030 · 2026-11-15 · 登录返回 500，查询了不存在的 Password 列

**实际异常**：用户提供服务器堆栈，SQLite Error 1: no such column: Password，发生在 AccountStore.FindByUserName 的 ExecuteReader，第 69 行；由登录接口第 129 行调用。

### 错题 028 · 2026-11-14 · SQL 原始字符串缩进不满足 C# 规则，报 CS8999

**实际验证**：运行服务器项目的 `dotnet build --no-restore --nologo`，编译失败，AccountStore.cs 第 21 行报 CS8999。

**原因**：构造方法的多行原始字符串中，CREATE TABLE 行前有 9 个空格，结束定界符行前有 10 个空格。内容行不满足结束行要求的公共缩进。错误发生在 C# 字符串解析阶段，SQL 尚未执行。

**修法**：统一原始字符串缩进，让每个非空内容行以结束定界符行的空白前缀开头。给用户提供整段可替换的建表字符串。成对四个双引号本身合法，不是引号数量导致此错。

**教训**：多行原始字符串的结束定界符决定公共缩进；不要只看 SQL 语法，还要看包裹 SQL 的 C# 字符串语法。

**状态**：用户修改后再次执行 `dotnet build --no-restore --nologo`，编译成功，0 个警告、0 个错误；缩进问题已通过编译验证，尚未测试实际数据库插入。

### 错题 027 · 2026-11-14 · 保存账号时混淆 SQL 括号、参数名和 C# 属性名

**来源**：服务器 AccountStore.cs 的 CreateAccount，以及 Program.cs 的 UserAccount 声明。

**代码检查确认**：INSERT INTO Accounts 后的列名列表写成 `{PlayerID,UserName,Nickname,PasswordHash}`，应使用圆括号；SQL 使用 `$nickname`，绑定却写成 `$nickName`；UserAccount 定义 UserName、PasswordHash、Nickname、playerId，调用却使用 PlayerId、userName、nickName、passwordHash，属性名不对应。

**修法**：统一账号属性为 UserName、PasswordHash、Nickname、PlayerId；SQL 列名列表改成 `(PlayerId, UserName, Nickname, PasswordHash)`；四个 SQL 参数名与 AddWithValue 的第一个参数保持一致，第二个参数使用实际存在的账号属性。

**教训**：SQL 列名、SQL 参数名、C# 属性名是三个不同层次。参数绑定负责把它们接起来，不会自动修正拼写或大小写。SQL 列名列表用圆括号，不能沿用 C# 的大括号习惯。

**状态**：后续读文件确认 SQL 列名列表已使用圆括号、四个参数名及 C# 属性名已对应；编译检查不再报告属性不存在，现因独立的 CS8999 缩进错误未通过（见 028）。尚未执行数据库插入。SQL 中的 PlayerID 与表中 PlayerId 不应和 C# 属性大小写规则混为一谈。成对的四个双引号本身合法。

### 错题 008 · 2026-10-11 · Vector2 的两个分量写反了

```csharp
rb.velocity = new Vector2(moveSpeed, rb.velocity.x);   // ← 横向和纵向搞混
```

`Vector2(x, y)`：第一个是横向，第二个是纵向。写反之后，纵向被设成了"当前横向速度"：

| 状态 | 纵向被设成 | 玩家看到 |
| --- | --- | --- |
| 原地不动 | `velocity.x` = 0 | 跳不起来 |
| 向右跑 | 3 | 往上弹，能跳 |
| 向左跑 | **-3** | 往下压，更跳不起来 |

正确写法：`rb.velocity = new Vector2(rb.velocity.x, jumpForce);`

**教训**：**遇到"有时候能行、有时候不行"，先怀疑参数顺序或分量位置。** 这类错误编译器不会报，只会让行为变得"看情况"——那种症状最难查。

### 错题 007 · 2026-10-11 · 15 个报错，其实只有一个根因

**当时的情况**：`SettingPanel.cs` 编译报了 15 个错，看着像"到处都有问题"。

**真正的原因**（一行）：

```csharp
public override void Init()
{
    public SettingData settingData = GameDataMgr.Instance.settingData;   // ← 方法体里写了 public
```

`public` 是**访问修饰符**，只能用在类级别（字段、方法、属性）。方法体里声明变量就是普通局部变量，不能加修饰符。

**为什么变成了 15 个错误**：编译器读到不合法的 `public` 时，以为 `Init` 的方法体**就此结束了**，于是把后面每一行都当成"类级别的成员"来解析——`btnMusic.onClick.AddListener(...)` 放在类级别当然非法，于是连环报错。

**教训**：

- **一堆错误先看第一条。** 后面的往往是它带出来的；改掉根因，十几条会一起消失
- **访问修饰符只在类里用。** 出现在方法体里，一定是写错了

**快速定位技巧**：第一条错误如果是 `} expected` 或 `Invalid token`，八成是前面某个括号或修饰符写错了——**往上找，别顺着往下看**。

### 错题 005 · 2026-10-10 · 改一半等于没改（同一个 bug 的第二个症状）

**当时的症状**（看着是两个，其实是同一个根源）：

1. 点按钮后面板「应该被销毁」，但没有
2. 点「关于」→ 点「返回」→ 再点「关于」，失效了

**症状一的因果链**：

```
点「返回」→ HidePanel<AboutGamePanel>() → HideMe() 把 alpha 从 1 淡到 0
                                        → 但 Update 里从来没调用 hideAction
                                        → 面板永远不销毁，字典条目永远不清
```

```
② 就算点到了，ShowPanel<T>() 发现字典里已经有它，直接 return
   → 没有调用 ShowMe() → alpha 还停在 0 → 依然看不见
```

- **一个 bug 的修法往往是好几处**，只改一处，症状会换个样子再冒出来
- **改完要按最长的那条路径走一遍**。这次的长路径是「关于 → 返回 → 关于」，而不是点一下看效果

→ 补救动作：把这一处当成**当前唯一待办**，改完立刻去 Hierarchy 里确认对象真的消失（不是变透明，是不在了），再做别的。

### 错题 001 · 2026-10-10 · 一个条件写反，连锁塌方

**当时的症状**：点按钮，新面板出现了，旧面板不消失。看起来像"隐藏功能有 bug"。

**真正的原因**（一行）：

```csharp
_group = GetComponent<CanvasGroup>();
if (_group != null) _group = gameObject.AddComponent<CanvasGroup>();   // 方向反了
```

写反之后，两个方向都通向同一个结果 —— **`_group` 恒为 null**：

- 预制体上**没有** CanvasGroup → 条件不成立 → 不添加 → null
- 预制体上**已经有** CanvasGroup → 又去 AddComponent → Unity 报"Cant add because already added"并**返回 null** → 覆盖成 null

**连锁反应**（这才解释了症状）：

1. 按钮回调第一行 `ShowPanel<pingtai2>()`
2. 它创建新面板，然后调 `panel.ShowMe()`
3. `ShowMe()` 第一行 `_group.alpha = 0;` → **空引用，抛异常**
4. 异常一路抛回你的按钮回调 → **回调剩下的代码被中断**
5. 第二行 `HidePanel<pingtai1>()` 根本没执行 → 旧面板当然不隐藏

**教训**：

- "没有就补上"这类**补偿式代码**，条件是"缺少时"（`== null`）
- 这类错误**不会报错**，只会悄悄变成 null，然后在很远的地方以另一个面目炸出来
- **别把不相关的事串在一个回调里**。如果顺序是"先隐藏旧的、再显示新的"，即使中间出错，至少旧面板能正常退场
- 一个操作里有两件事时，先做**更安全**的那件（这里是"隐藏"），再做可能失败的那件

### 储备区（还没踩，但很常见，先记着）

- **按钮事件挂了两条**：第一条把按钮所在的物体销毁了，Unity 会跳过这个按钮剩下的监听。
- **`Resources.Load` 返回 null**：预制体名字和类名差一个字就加载不到，屏幕什么都不变。
- **`DontDestroyOnLoad` 对象的子物体不会随场景销毁**：UI Canvas 是常驻的，所以它的子物体（面板）会跟着你进下一个场景。切场景前要主动关掉所有面板。
- **`SceneManager.LoadScene` 只能加载 Build Settings 里的场景**：否则报 `Scene 'xxx' couldn't be loaded because it has not been added to the build settings`。
- **边遍历字典边删元素会抛 `Collection was modified`**：要先把 key 复制一份再遍历。
- **`AudioMixer.SetFloat` 要传分贝，不是 0~1**：滑条值要用 `Mathf.Log10(v) * 20f` 换算，`v ≈ 0` 时直接给 -80（静音）。直接把 0~1 塞进去，会听起来"几乎没变化"，因为音量是"感觉"线性而不是数值线性。
- **程序刷新界面时给滑条赋值，会触发它的回调**：加一个 `_refreshing` 标志挡住，否则"界面改数据、数据又改界面"，会读到半路的值。
- **设置不要用 ScriptableObject 存**：它的强项是"配置"，但打包后运行时的改动**不会保留**。设置属于"要持久化的状态"，得存 PlayerPrefs 或文件。
- **两种 JSON 库不能混用**：`JsonUtility` 只认 public 字段（不认属性、不认 Dictionary），`LitJson` 规则不同。同一份数据用一个存、用另一个读，字段对不上时会**静默变成默认值**。
- **`for` 循环里给按钮加监听会踩闭包坑**：`AddListener(() => SwitchTo(i))` 捕获的是**变量本身**，循环结束后 `i` 已经等于数组长度。表现是"点所有按钮都没反应"（有边界判断时）或直接越界报错。要在循环里先 `int index = i;` 再捕获 `index`。（`foreach` 的循环变量是每次新建的，没这个问题。）
- **`GetComponentInParent` 依赖层级结构**：它往上找，但"父物体到底是谁"会随层级调整而变。改动层级后这行代码会**静默拿到 null 或错误对象**。原型期能用，正式一点的做法是让父对象主动把引用传下来，或者在 Inspector 里拖引用。
- **别用"隐藏父物体的所有子物体"来切页**：父物体的子物体不止有页，还有 Tab 栏、背景、标题、返回按钮。"全隐藏再显示一个"会把 Tab 栏自己也藏掉，界面当场变空。要么把所有页放进一个**只装页的容器**再遍历它，要么用显式引用把按钮和页对应起来。
